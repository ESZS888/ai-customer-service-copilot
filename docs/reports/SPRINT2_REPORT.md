## 2. 分阶段实现

### 阶段一：存储与接口

- 复用 FastAPI、原 LangGraph 五节点；新增统一 `chat_service.run_chat`，HTTP、SSE、CLI 共享执行和保存逻辑。没有新增 Agent、ORM、服务或运行依赖。
- SQLite 三张表：`chat_turns` 保存有效请求、会话、来源、状态、意图、耗时与成功响应快照；`tickets` 保存工单当前状态；`events` 保存请求、工具执行、工单创建和状态变更。
- 编号由持久化层生成 `TK-<UUID>`，模型草稿中的编号和持久化字段不可信。工单、成功请求、相关事件在一个事务中提交，提交成功后才返回“工单已保存”。写失败会回滚且不报保存成功。
- 支持用户明确提供的多个订单编号，保留原始诉求与 AI 草稿；未提供则为空。编号关联不代表已验证订单存在或归属。
- 状态：`open（待处理） → in_progress（处理中） → resolved（已处理）`。已处理可填写原因后回到处理中。同状态可追加说明，历史保留；已处理必须有非空说明。版本不一致返回 409，避免旧页面覆盖新记录。
- 同 `request_id` 且内容/来源一致的成功重放返回原响应快照，不再次调用模型或创建工单。处理中的重复请求返回 409；内容或来源冲突返回 409；失败/中断需新请求编号。**聊天快照保留创建时状态；详情接口提供最新状态**。
- 单进程、单 worker 本机运行；每次操作独立连接、外键、5 秒 busy timeout、短事务，模型请求期间不持有数据库事务。启动时将遗留 processing 标记 interrupted；没有自动执行或自动重试退款。schema 版本 2 带本次阶段内的增量意图列兼容迁移，未删除已有数据。
- 基础脱敏覆盖常见手机号、邮箱、显式凭据字段与 sk-形式；不保存认证头或原始异常。它不是通用隐私检测，不应输入真实客户敏感信息。
- 阶段一最终 **37 项工程测试通过** 后才开始工单页；含新进程读取工单状态、状态/事件回滚、幂等与并发领取测试。

默认数据库：`backend/storage/copilot.sqlite3`。路径从代码位置确定，不随启动目录变化；可用 `DB_PATH` 覆盖。私有 GLM 配置继续由原后端机制读取，没有查看或输出真实 Key；LLM 客户端、模型配置值和原有图拓扑未修改。

### 阶段二：商家工单页

路径 `/merchant/tickets`。支持来源切换、编号/摘要/原话搜索、三状态筛选、分页、详情、原始诉求、AI 摘要、关联订单、处理说明、版本与变更历史。切换筛选清空旧详情；请求失败显示错误，保存后重新读取真实记录。

保留聊天页，新增商家入口、保存确认、详情链接。卡片明确“创建时待处理”，避免将历史回复当成当前状态。浏览器为每个新问题生成请求编号；网络结果未知时重发同文可复用编号，后端已明确失败后允许新请求。conversation_id 仅关联本页会话，不赋予模型多轮记忆。

已用真实 GLM 从浏览器创建一条标明“演示验收”的投诉，核对正文/卡片/列表/详情编号一致；通过页面保存处理中、填写说明后标记已处理，刷新及服务重启后仍为版本 3，三条历史完整。还检查了关键词搜索、已处理筛选和待处理空列表。未进行真实商家用户测试。

### 阶段三：运营概览

路径 `/merchant/dashboard`。所有计数、比例、分布、耗时和明细来自 SQLite API；没有预置统计值或前端伪造增长。支持数据来源、开始/结束日期、刷新、工单状态入口、失败/全部请求明细与分页。

| 指标 | 实际口径 |
|---|---|
| 咨询量 | 按接收时间筛选的有效唯一 request_id；同编号重放不新增；422、409 和存储接受请求前的失败不进入咨询量 |
| 独立会话数 | 同范围内唯一 conversation_id，不等于独立买家数；未传会话编号时后端生成一个 |
| 意图分布 | 沿用最终 Agent 路由；订单类按明确物流关键词细分，general 中政策关键词细分。复合订单/物流只计物流一次；失败/处理中未分类为 unknown。不是新训练的语义分类器 |
| 期间新建工单状态 | 按工单创建时间筛选，展示这些工单的最新状态，不是历史时点快照 |
| 全量当前待处理 | 当前来源全部日期的 open + in_progress，与期间工单单独标注 |
| 失败率 | (failed + interrupted) / (succeeded + failed + interrupted)；processing 单列，零终态显示“—”，不伪装 0% |
| 响应耗时 | 分成功/失败展示有记录样本的中位数和样本量；统计至结果保存前，中断未知耗时不填 0 |
| 失败明细 | 安全错误类别、基础脱敏问题、请求编号、时间、耗时；业务追问/查无数据不算执行失败 |

时间以 UTC 存储，筛选按 Asia/Hong_Kong（UTC+8）日期含首尾转换；默认全部日期。状态卡片点击进入对应状态的**全量**工单列表，页面已说明不沿用 Dashboard 日期。图表和请求明细分别请求 API，若同时有新流量可能短暂处于不同快照，手动刷新可更新；本轮最终复算在评测停止后进行。

- 未接入真实平台、真实订单权限、人工通知/接单、自动退款、多店铺、登录鉴权；适用于本机单店演示，不开放真实数据公网访问。
- 保持单轮客服；来源标签由客户端提供，用于本机分析隔离，不是安全权限。意图分布沿用粗分类，不能当作独立分类准确率。
- 没有自动创建工单覆盖所有答不出的问题；沿用 Sprint 1 投诉/售后申请路由。信息不足继续追问，没有依据继续说明边界。
- 没有重置/删除工单界面、完整数据导出或自动备份。持久化依赖这个本地数据库文件，删除文件会丢数据；移动项目时连同 storage 保留。备份时先停止后端，再复制该数据库到安全位置，随后重新启动。当前源码包故意不带已有数据。
- 存储在接受请求前彻底不可用时无法记入同一数据库，不能保证 Dashboard 统计所有网络/进程故障；启动中断恢复也只适用于此单 worker 模式。
- 未统计模型账单金额、满意度、真实解决率、节省人工或销售转化。当前依赖漏洞和 Docker 配置沿用原审计的遗留结论，本轮未进行公网/容器部署验收。
