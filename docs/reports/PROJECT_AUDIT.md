# 第一阶段项目审计（公开摘要）

审计时间：2026-10-17。上游基准提交：`9a7888023b5bc64b9bf0ca78ce9e94dc750aec42`。

这是改进前的历史审计；下述缺陷不代表当前版本仍全部存在。

## 当时的实际实现

Next.js 聊天页 → FastAPI → 进程内 LangGraph：Router 按意图分配 Knowledge、Tool 或 Escalation，再由 Summary 生成回复。数据来自 DemoDataProvider：3 个商品、3 个订单、2 条物流、9 篇知识文档和 3 类退换货政策。

检索使用关键词匹配，不是 embedding/向量数据库。每轮只传当前输入，页面有历史不等于模型有多轮记忆；SSE 是执行后回放，不是逐 token 真流式。

## 实际发现及后续处理

| 审计发现 | 产品影响 | 后续处理 |
|---|---|---|
| 泛商品列表和商品编号检索失配 | 用户无法可靠获得商品信息 | Sprint 1 增加目录/编号优先和无证据策略 |
| 工具、知识关键事实在 Summary 截断/丢失 | 政策、商品、物流可能答错 | Sprint 1 保留关键事实，减少重复生成 |
| 投诉对象编号与正文编号不同 | 用户无法可信追踪 | 程序控制编号，Sprint 2 提交数据库后确认 |
| 工单仅在内存，无实际人工接单 | 错误承诺、刷新丢失 | Sprint 1 修复措辞，Sprint 2 保存工单和状态 |
| 缺少参数和 JSON 严格校验 | 异常或执行无依据查询 | Sprint 1 补校验与有限兜底 |
| 无商家运营数据闭环 | 看不到待办和失败请求 | Sprint 2 新增事件记录与 Dashboard |

原版单次真实业务检查：商品目录请求执行成功但回答未通过；演示订单和物流查询可用；投诉生成对象但正文编号不一致。单次场景检查不构成准确率统计。

原审计时没有可执行自动化测试；后续已建立测试和评测，见 [评测索引](../evaluation/README.md)。

## 环境与边界

Windows 上完成过 Python 3.13.5、Node 24.19.0 的本地启动。原审计 Docker 引擎可连接，但没有完成镜像或云部署验收。依赖扫描发现风险，本轮未统一升级，公开源码不代表适合公网生产使用。

保持单店演示，不接真实电商平台，没有登录鉴权、订单归属校验或真实退款执行。凭据使用后端私有环境配置，不随公开材料发布。
