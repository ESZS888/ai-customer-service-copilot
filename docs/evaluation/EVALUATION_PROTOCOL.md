# Sprint 1 固定评测协议

## 顺序与边界

先冻结 `backend/evals/cases.jsonl` 和 `score.py`，在未修改 `backend/app/` 的代码上完成 baseline，然后才允许修改业务代码。每轮保存源文件 SHA-256 清单、无密钥源码快照、同一份案例与评分器；不得覆盖已有结果目录。最终对比必须验证案例和评分器哈希相同。

数据全部来自 DemoDataProvider：3 个商品、3 个订单、2 条物流、9 篇知识文档。真实 GLM API 调用只用于处理这些演示提问；不连接真实商家订单，不执行付款、退款或人工转接。

## 可比条件

- 同一 GLM 配置，原调用参数沿用；评测不把真实认证信息写入文件。
- 两轮均使用最多 2 条工作线程，各自 requests Session；只隔离连接，不改请求内容、temperature、max_tokens 或模型响应。
- 仅 DemoProvider 的物流当前日期固定为 2026-10-17 12:00，预计日期固定为 10月18日/20日；不冻结真实请求耗时、模型响应和工单生成时间。
- 记录完整业务输出、路径、工具结果、实际调用次数、API 返回用量（若有）及秒级耗时。异常只保存类型，避免上游错误内容泄露信息。
- 失败样本同样计入分母。不因结果不好删除、改题或放宽评分；额外尝试单独保存，不替换首次正式轮次。

## 评分与解释

36 条含商品8、订单6、物流5、退款政策5、投诉5、模糊越界4、诱导冲突3。28 条 development、8 条 acceptance 仅表示固定用途。该案例集由本次开发者编写并可见，最终结果是小样本固定回归，**不宣称盲测、生产准确率或真实商业收益**。

每条必须同时满足：有非空回复、所有标注事实匹配、没有禁用事实、必要工具执行/缺参数时不执行、必要临时工单存在且正文编号一致，以及展示文案未检出真实转人工或退款执行承诺。事实采用可选表达的正则组，不要求逐字复述。固定规则不等同于完整语义理解；须阅读回复检查漏判，人工发现另行披露，不静默改自动分数。

原型没有持久化系统；C04/C05 是同一句话的两次独立请求，要求各自编号一致且彼此不碰撞，不测试同 request_id 的幂等性。真实持久化/状态流转/重试去重留给下一 Sprint。

主要指标为整条场景通过数/36、分场景通过数、执行异常数、临时工单编号一致性、展示中的不实承诺数、实际模型调用数与请求耗时中位数。usage 缺失明确记录，不将缺失值当实际 0 成本；不估算金额，不报告未经测量的人工节省率。

验收约束：期望至少33/36场景通过，且不产生虚假退款/转人工承诺；如达不到必须如实报告，不能把目标写成结果。工程替身测试与模型业务评测分开统计。
