# 产品取舍与个人贡献边界

目标用户和痛点来自当前产品假设，未进行真实商家访谈。已有开源原型是起点；作品集价值在于识别可靠性和业务闭环缺口，并以实际记录验证改进。

| 决策 | 原因 | 验收方式 |
|---|---|---|
| 先做可靠性，再加商家功能 | 错价格、错工单号和虚假承诺会破坏信任 | 固定案例、未知数据/缺参数/承诺边界测试 |
| SQLite 单库 | 单店本机演示，优先降低两周 MVP 的实现与运行成本 | 新进程及真实重启后可查，事务失败不报成功 |
| 只保留三状态 | 足以展示投诉处理闭环 | 说明必填、状态/列表/详情/历史一致 |
| 指标从真实事件汇总 | 静态展示值不能支持产品判断 | SQL 与 API 逐项复算，来源分开 |
| 不展示满意度和解决率 | 没有用户确认反馈或可信业务结果 | UI 不把执行成功/已处理写成问题解决 |
| 复用原五节点 | 当前瓶颈是事实与状态管理，不需要更多 Agent | 保留工作流，必要逻辑放服务和 Repository |

产品负责人工作：需求与边界、竞品启发、MVP 优先级、状态和指标口径、评测与验收。AI 工具辅助：代码实现、修复、运行检查和文档整理。原作者贡献：基础架构、原始聊天与 Agent 原型、演示 Provider。没有将开源原型或 AI 辅助实现包装为全部独立原创代码。

下一步优先邀请测试者完成投诉创建、商家处理和数据核对任务，记录困难并迭代；不以固定 36 条全通过替代用户验证。
